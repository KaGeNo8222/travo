# TRAVO — Personal Travel Planner & Shopping Companion

TRAVO เป็นแอปวางแผนทริปส่วนตัวแบบ **offline-first PWA** ออกแบบให้ใช้บน iPhone (Safari และแบบติดตั้งลงหน้าจอโฮม) เป็นหลัก ข้อมูลทั้งหมดเก็บอยู่ในเครื่องด้วย IndexedDB ไม่มีบัญชีผู้ใช้ ไม่มีเซิร์ฟเวอร์ และไม่มี analytics

## ความสามารถหลัก

| หมวด | รายละเอียด |
| --- | --- |
| ทริป | สร้าง / แก้ไข / ทำสำเนา (เลื่อนวันได้) / เก็บถาวร / ลบ, รูปปก, สร้างวันอัตโนมัติจากช่วงวันที่, สถานะแสดงผลอัตโนมัติตามวันที่ใน timezone ของทริป |
| แผนรายวัน | timeline ตามเวลา + รายการที่ยังไม่กำหนดเวลา (จัดลำดับได้), ย้ายวัน, ทำสำเนา, เสร็จ/ข้าม, เตือนเวลาซ้อน, กิจกรรมข้ามเที่ยงคืน, ไฮไลต์กิจกรรมปัจจุบัน/ถัดไป |
| สถานที่ | ลิงก์ Google Maps (เก็บลิงก์ต้นฉบับไว้), อ่านพิกัดเฉพาะที่อยู่ในลิงก์จริง, ตรวจสถานที่ซ้ำ, หมวดหมู่กำหนดเองได้, เพิ่มลงวันได้ทันที |
| ช้อปปิ้ง | การ์ดเน้นรูป + โหมด checklist, ถ่ายรูป / คลังรูป / วางจากคลิปบอร์ด, ซื้อบางส่วน, กรองตามสถานะ/ผู้รับ/ร้าน, ยอดประมาณการและยอดจ่ายจริง, ดูรูปเต็มจอเพื่อให้พนักงานร้านดู |
| การจอง | เที่ยวบิน (timezone ขาไป-ขาถึงต่างกันได้), ที่พัก, รถไฟ, ตั๋ว ฯลฯ, แนบ PDF/รูปแบบไม่แก้ไขไฟล์, รหัสการจองถูกซ่อนจนกว่าจะแตะ |
| ค่าใช้จ่าย | ยอดรวม, ตามหมวด, รายวัน, งบประมาณคงเหลือ, แปลงสกุลเงินด้วยอัตราที่ผู้ใช้กรอกเอง |
| ระบบ | ใช้งานออฟไลน์, สำรอง/กู้คืนเป็น ZIP (รวมไฟล์แนบ), ตรวจและซ่อมความถูกต้องของข้อมูล, ไทย/อังกฤษ, โหมดมืด |

## เริ่มต้นใช้งาน (Windows / macOS / Linux)

ต้องใช้ **Node.js 22.22 ขึ้นไป** (React Router 8 กำหนดไว้ พัฒนาและทดสอบกับ Node 24.19)

```bash
npm install
npm run dev        # เซิร์ฟเวอร์พัฒนา http://localhost:5173 (เปิดให้เครื่องอื่นในวง LAN เข้าได้)
npm test           # รัน automated tests ทั้งหมด (Vitest)
npm run typecheck  # ตรวจ TypeScript ทั้งแอป, config และ tests
npm run build      # typecheck + production build + dist/404.html
npm run preview    # เสิร์ฟ build จริงเพื่อทดสอบ service worker / ออฟไลน์
npm run icons      # สร้างไอคอน PNG ใน public/icons ใหม่ (ไม่ต้องใช้ตามปกติ)
```

ลองดูข้อมูลตัวอย่างได้จากปุ่ม **"ลองดูทริปตัวอย่าง"** ในหน้าแรก หรือ **ตั้งค่า → ข้อมูลตัวอย่าง** แอปจะไม่เติมข้อมูลตัวอย่างให้เองโดยอัตโนมัติ

### เปิดจาก iPhone ระหว่างพัฒนา

`npm run dev` จะแสดง Network URL เช่น `http://192.168.1.20:5173` ให้เปิดจาก iPhone ที่ต่อ Wi-Fi วงเดียวกัน แต่การเปิดผ่าน **HTTP บนวง LAN ไม่ถือเป็น secure context** จึงมีข้อจำกัด:

- service worker ไม่ทำงาน (ทดสอบออฟไลน์และติดตั้งแบบ PWA จริงไม่ได้)
- การวางรูปจากคลิปบอร์ดและการแชร์ไฟล์อาจใช้ไม่ได้
- ส่วนอื่นยังใช้ได้ตามปกติ (แอปมี fallback สำหรับสร้าง UUID แล้ว)

หากต้องการทดสอบแบบครบ ให้ deploy ขึ้นโฮสต์ที่เป็น HTTPS (ดูหัวข้อถัดไป) แล้วทำตาม [docs/IPHONE_TESTING.md](docs/IPHONE_TESTING.md)

## Deploy

ผลลัพธ์ของ `npm run build` คือไฟล์ static ในโฟลเดอร์ `dist/` วางบนโฮสต์ใดก็ได้ที่เป็น **HTTPS** (PWA และ service worker ต้องใช้ HTTPS) เงื่อนไขมีสองข้อ:

1. URL ที่ไม่ใช่ไฟล์ต้อง fallback ไป `index.html` (SPA routing)
2. `sw.js` ไม่ควรถูก cache นาน เพื่อให้ผู้ใช้ได้รับอัปเดต

| โฮสต์ | วิธี |
| --- | --- |
| **GitHub Pages (แนะนำ)** | มี workflow `.github/workflows/deploy.yml` อยู่แล้ว ทุกครั้งที่ push/อัปโหลดเข้า `main` จะ test → build → deploy ให้อัตโนมัติ และตั้ง sub-path ตามชื่อ repo เอง (ดูหัวข้อถัดไป) |
| Netlify / Cloudflare Pages | build command `npm run build`, publish dir `dist` — มี `public/_redirects` ให้แล้ว |
| Vercel | framework "Vite", output `dist` — มี `vercel.json` (rewrite + no-cache ให้ `sw.js`) |
| เซิร์ฟเวอร์อื่น | ตั้งค่า fallback ไป `/index.html` และใส่ `Cache-Control: no-cache` ให้ `/sw.js` ถ้าอยู่ใต้ sub-path ให้ build ด้วย `TRAVO_BASE=/<path>/` (PowerShell: `$env:TRAVO_BASE='/<path>/'; npm run build`) |

### Deploy ขึ้น GitHub Pages

1. สร้าง repository ใหม่บน GitHub แบบ **Public** (GitHub Pages ฟรีต้องเป็น public ซึ่งเปิดเผยแค่ซอร์สโค้ด ข้อมูลทริปยังอยู่ในเครื่องผู้ใช้เท่านั้น)
2. อัปโหลดซอร์สโค้ด โดยไม่รวม `node_modules` และ `dist`
   - **มี git:** `git init`, `git add .`, `git commit`, แล้ว push เข้า branch `main`
   - **ไม่มี git (อัปโหลดผ่านหน้าเว็บ):** รัน `npm run prepare:upload` ซึ่งจะสร้างโฟลเดอร์ `../TRAVO-github-upload` ที่แบ่งไฟล์เป็นชุดละไม่เกิน 100 ไฟล์ (ข้อจำกัดของหน้าเว็บ GitHub) แล้วอัปโหลดตามลำดับที่ระบุใน `README-UPLOAD.txt`
3. **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions** (ทำก่อนอัปโหลดชุดสุดท้ายที่มีไฟล์ workflow)
4. ดูผลที่แท็บ **Actions** เมื่อ "Deploy to GitHub Pages" ขึ้นสีเขียว แอปจะอยู่ที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ-repo>/`
5. ครั้งต่อไปที่แก้โค้ด ให้อัปโหลดไฟล์ที่เปลี่ยนเข้า `main` อีกครั้ง GitHub จะ deploy ใหม่ให้เอง และแอปบน iPhone จะขึ้นแถบให้อัปเดต

ถ้า test หรือ build ล้มบน GitHub จะไม่มีการ deploy เวอร์ชันนั้น เวอร์ชันเดิมที่ใช้งานอยู่จึงไม่เสีย

เมื่อมีเวอร์ชันใหม่ แอปจะขึ้นแถบ **"มี TRAVO เวอร์ชันใหม่"** ให้ผู้ใช้กดอัปเดตเอง ไม่ reload ทับระหว่างกรอกข้อมูล

## ติดตั้งบน iPhone

1. เปิด URL ของแอปด้วย **Safari** (ต้องเป็น HTTPS)
2. แตะปุ่ม **แชร์** → **เพิ่มไปยังหน้าจอโฮม** → **เพิ่ม**
3. เปิดแอปจากไอคอน TRAVO บนหน้าจอโฮม เปิดครั้งแรกขณะออนไลน์เพื่อให้ cache ไฟล์ครบ (จะขึ้นข้อความ "พร้อมใช้งานแบบออฟไลน์แล้ว")
4. ตั้งแต่นั้นเปิดได้แม้ไม่มีอินเทอร์เน็ต

แนะนำ iOS 16.4 ขึ้นไป (build target ของ Vite รองรับ Safari 16+)

## ข้อมูลและความเป็นส่วนตัว

- ข้อมูลทั้งหมด (รวมรูปและไฟล์แนบ) อยู่ใน IndexedDB ชื่อ `travo_db` บนเครื่องนี้เท่านั้น ไม่ถูกส่งไปที่ใด
- **ข้อมูลไม่ได้เข้ารหัส** การป้องกันอาศัยรหัสล็อกเครื่องของ iPhone
- ไม่ควรเก็บเลขหนังสือเดินทางหรือเอกสารยืนยันตัวตนที่อ่อนไหวมาก รหัสการจองถูกซ่อนเป็น `••••` โดยค่าเริ่มต้น
- ไม่มี API key หรือ secret ในโค้ด และไม่เรียก Google Maps API (ใช้เฉพาะ Maps URL ทางการ)
- Safari อาจลบข้อมูลของเว็บที่ไม่ได้ใช้นานถ้า **ไม่ได้** ติดตั้งลงหน้าจอโฮม แอปที่ติดตั้งแล้วจะขอ persistent storage ให้อัตโนมัติ และดูสถานะได้ที่ **ตั้งค่า → พื้นที่จัดเก็บ**

## สำรองและกู้คืนข้อมูล

**ตั้งค่า → สำรองข้อมูล → สร้างไฟล์สำรองข้อมูล** จากนั้นกด **"บันทึกไปที่แอปไฟล์ / แชร์"** แล้วเลือก "บันทึกไปยังไฟล์" (เก็บใน iCloud Drive ได้) ไฟล์สำรองอยู่ในความดูแลของผู้ใช้เอง **แอปไม่ได้ซิงก์ iCloud อัตโนมัติ**

โครงสร้างไฟล์:

```text
TRAVO_Backup_<เวลา>.zip
└── TRAVO_Backup/
    ├── manifest.json      # format/schema/app version, เวลา export, จำนวน record, metadata ของไฟล์แนบ
    ├── database.json      # ทุกตาราง (ยกเว้น binary ของไฟล์แนบ) โดยคง id และความสัมพันธ์เดิม
    └── attachments/<id>   # ไฟล์แนบแบบ binary ไม่บีบอัดซ้ำ
```

การกู้คืน (**ตั้งค่า → กู้คืนข้อมูล**):

- ไฟล์จะถูกตรวจทั้งหมดก่อน ได้แก่ manifest, เวอร์ชัน schema, Zod validation ทุก record, ความสัมพันธ์ (เช่น กิจกรรมต้องอยู่ในวันของทริปเดียวกัน) และขนาดไฟล์แนบ ถ้าไม่ผ่านจะแสดงรายละเอียดและ **ไม่แตะข้อมูลเดิม**
- ลิงก์เสริมที่ขาด (เช่น รูปที่หายไป) จะถูกซ่อมให้อัตโนมัติพร้อมแจ้งจำนวน
- **รวมกับข้อมูลเดิม:** ถ้าทริปมีอยู่แล้ว เลือกได้ว่าจะ ข้าม / แทนที่ทริปนั้น / นำเข้าเป็นสำเนา (สร้าง id ใหม่ทั้งชุด)
- **แทนที่ทั้งหมด:** ล้างข้อมูลในเครื่องแล้วใช้ไฟล์สำรอง (มีหน้ายืนยันก่อนทำ)
- การเขียนทั้งหมดอยู่ใน Dexie transaction เดียว ถ้าล้มกลางทาง ข้อมูลเดิมจะคงอยู่ครบ และแอปจะแจ้งสำเร็จหลัง transaction commit แล้วเท่านั้น
- ไฟล์สำรองจาก schema ที่ใหม่กว่าแอปจะถูกปฏิเสธ ส่วนไฟล์จาก schema เก่าจะผ่านขั้น migration ก่อน

**ข้อจำกัดเรื่องขนาด:** การสร้างและอ่าน ZIP ทำในหน่วยความจำทั้งหมด บน iPhone แนะนำให้ข้อมูลรวมไม่เกินประมาณ **250 MB** (แอปจะเตือนเมื่อเกิน) รูปสินค้าถูกย่อให้ด้านยาวไม่เกิน 1600 px จึงมักมีขนาดราว 150–400 KB ต่อรูป ถ้าข้อมูลใหญ่มาก ให้ปิดแอปอื่นก่อนสำรอง หรือลบ PDF ขนาดใหญ่ที่ไม่ใช้แล้ว

## สถาปัตยกรรม

```text
src/
├── app/            App, router, TripLayout, providers (ธีม/ภาษา, TripContext)
├── components/     ui/ (Button, Field, Sheet, Images…), layout/, trip/, itinerary/, places/,
│                   shopping/, bookings/, expenses/, settings/
├── pages/          8 หน้าตาม spec + MorePage
├── db/             database.ts (Dexie), schema.ts (Zod), migrations.ts, seed.ts, repositories/
├── services/       business logic + transactions (trip, itinerary, place, shopping, booking,
│                   expense, image, attachment, backup, category, integrity)
├── hooks/          live queries (useLiveQuery), object URL, เวลาปัจจุบัน, viewport
├── i18n/           th.ts (ต้นฉบับ key), en.ts (TypeScript บังคับให้ครบทุก key), format, labels
├── stores/         Zustand: toast และ dialog (state ชั่วคราวเท่านั้น)
├── utils/          time, money, maps, schedule, shopping, spending, files, storage
└── dev/            ข้อมูลตัวอย่าง (โหลดเฉพาะเมื่อผู้ใช้กดเอง)
tests/              Vitest + fake-indexeddb + Testing Library
```

การแบ่งชั้น: **pages/components** อ่านข้อมูลผ่าน hooks (live query) และเขียนผ่าน **services** เท่านั้น ส่วน services จะ validate ด้วย Zod ตรวจความสัมพันธ์ และเขียนใน transaction

### ฐานข้อมูล (`travo_db`, schema v1)

| ตาราง | index |
| --- | --- |
| trips | `id, startDate, status, updatedAt` |
| trip_days | `id, tripId, &[tripId+date]` (หนึ่งวันต่อหนึ่งวันที่) |
| places | `id, tripId, category, categoryId, [tripId+category]` |
| activities | `id, tripId, tripDayId, placeId, [tripDayId+sortOrder]` |
| shopping_items | `id, tripId, status, shopPlaceId, [tripId+status]` |
| bookings | `id, tripId, type, placeId, [tripId+type]` |
| attachments | `id, tripId, [ownerType+ownerId]` |
| expenses | `id, tripId, expenseDate, activityId, shoppingItemId, [tripId+expenseDate]` |
| categories | `id, sortOrder` |
| trip_settings | `tripId` |
| app_settings | `key` |

ข้อที่ต่างจาก spec ตัวอย่าง:

- ไม่ทำ index `isVisited` เพราะ IndexedDB ทำ index ค่า boolean ไม่ได้ (index จะว่างเปล่าเสมอ)
- `trip_settings` มี `budgetCurrency` และ `otherRatesToTHB` เพิ่ม เพื่อให้งบประมาณและทริปหลายสกุลเงินคำนวณถูกต้อง

**การเพิ่ม schema version:** ใน `src/db/migrations.ts` ให้คง `db.version(1)` ไว้ แล้วเพิ่ม `db.version(2).stores(...).upgrade(...)` และเพิ่มขั้นแปลงข้อมูลแบบเดียวกันใน `BACKUP_UPGRADES` เพื่อให้กู้คืนไฟล์สำรองเก่าได้ จากนั้นเพิ่ม `SCHEMA_VERSION`

### กฎทางธุรกิจที่สำคัญ

- **แหล่งข้อมูลการเงินมีที่เดียว:** ยอดช้อปปิ้งคำนวณจาก `shopping_items` (จำนวนที่ซื้อ × ราคาจริง หรือราคาประมาณถ้ายังไม่กรอกราคาจริง) การกดว่าซื้อแล้ว **ไม่สร้าง expense** ถ้าผู้ใช้สร้าง expense ที่ผูกกับสินค้า ยอดนั้นจะใช้แทนยอดของสินค้า จึงไม่นับซ้ำ
- **การปัดเศษเงิน:** คำนวณเป็นหน่วยย่อยจำนวนเต็มตามสกุลเงิน (THB 2 ตำแหน่ง, JPY 0) ปัดแบบ half-up ตอนบันทึก การแปลงสกุลเงินใช้ BigInt แปลงทีละรายการแล้วจึงรวม อัตราแลกเปลี่ยนเก็บได้ 6 ตำแหน่ง และระบุชัดว่าเป็น "อัตราที่ผู้ใช้กำหนดเอง"
- **Expense กับอัตราแลกเปลี่ยน:** ถ้าไม่ได้ใส่อัตราเฉพาะรายการ จะใช้อัตราของทริป และเมื่อแก้อัตราของทริป `amountTHB` จะถูกคำนวณใหม่ ส่วนรายการที่ใส่อัตราเองจะคงอัตราเดิมไว้
- **สถานะช้อปปิ้ง:** `purchased` เฉพาะเมื่อซื้อครบจำนวน ถ้าซื้อบางส่วนสถานะยังเป็น `to_buy` และ UI แสดงว่า "ซื้อแล้ว x/y"
- **การเปลี่ยนวันที่ทริป:** ถ้าวันที่จะถูกตัดออกมีกิจกรรมหรือบันทึกอยู่ แอปจะถามก่อนเสมอ ให้เลือก "เลื่อนแผนตามวันเริ่มใหม่" หรือ "ย้ายไปวันที่ใกล้ที่สุด" ไม่มีกิจกรรมใดถูกลบเงียบ ๆ
- **เวลา:** วันที่เก็บเป็น `YYYY-MM-DD` และเวลาเก็บเป็น `HH:mm` ตาม timezone ของทริป ส่วนการจองเก็บเวลาท้องถิ่นพร้อม timezone ของต้นทาง/ปลายทางแยกกัน (เที่ยวบินข้ามคืนคำนวณระยะเวลาถูกต้อง) ส่วน timestamp ของระบบเป็น ISO UTC
- **การลบ:** ลบทริปจะลบทุกตารางที่เกี่ยวข้องใน transaction เดียว ลบสถานที่จะยกเลิกการเชื่อมโยงกับกิจกรรม/ช้อปปิ้ง/การจองโดยไม่ลบรายการเหล่านั้น หมวดหมู่ที่ยังมีสถานที่ใช้อยู่จะย้ายสถานที่ไปหมวด "อื่นๆ" ก่อนลบ
- **รูปภาพ:** รูปสินค้าและรูปปกถูกย่อด้วย Canvas (ด้านยาวไม่เกิน 1600/1920 px, JPEG คุณภาพ 0.85/0.8) แต่ถ้าไฟล์เล็กอยู่แล้วหรือย่อแล้วไม่เล็กลงจะเก็บไฟล์เดิม ส่วนเอกสารการจอง (PDF/รูป) เก็บแบบไม่แก้ไข

## การทดสอบ

`npm test` รัน 82 tests ใน 13 ไฟล์:

- **CRUD และความสัมพันธ์:** สร้างทริปพร้อมวัน, กิจกรรมต้องอยู่ในวัน/สถานที่ของทริปเดียวกัน, ย้าย/จัดลำดับ/ทำสำเนา, ลบสถานที่แล้วยกเลิกการเชื่อมโยง, ลบทริปแบบ cascade, ทำสำเนาทริป
- **วันที่และเวลา:** สร้างวันข้ามเดือน/ปี, DST ทั้งของเครื่องและของจุดหมาย, "วันนี้" ตาม timezone ของทริป, เที่ยวบินข้ามคืน, การเปลี่ยนวันที่ทริปทั้งสองแบบ

- **ไฟล์:** การตรวจชนิด/ขนาด, การเก็บเอกสารแบบไม่แก้ไข, ไม่มีไฟล์แนบค้างเมื่อเปลี่ยนหรือลบรูป
- **Backup/restore:** export → replace-all แล้วข้อมูลตรงเดิมทุก record, merge ทั้ง 3 แบบ, ปฏิเสธไฟล์ผิดรูปแบบ/schema ใหม่กว่า/ไฟล์แนบเสียหาย และข้อมูลเดิมไม่ถูกแตะ, rollback เมื่อเขียนล้มกลางทาง
- **ฐานข้อมูล:** version, seed หมวดหมู่, ข้อมูลยังอยู่หลังปิด-เปิดใหม่, unique index, integrity check/repair
- **UI:** ฟอร์มทริป (validation และการบันทึก), การ์ดช้อปปิ้ง, dictionary ไทย/อังกฤษครบทุก key และ smoke test ที่ render แอปทั้งตัวแล้วเปิดทุกหน้าด้วยทริปตัวอย่าง

## Known limitations

- **ไม่มีการซิงก์หรือคลาวด์:** ข้อมูลอยู่เครื่องเดียว ย้ายเครื่องได้ด้วยไฟล์สำรองเท่านั้น
- **ข้อมูลในเครื่องไม่ได้เข้ารหัส**
- **อัตราแลกเปลี่ยนต้องกรอกเอง** ไม่มีอัตราแบบเรียลไทม์ ยอดที่สกุลเงินไม่มีอัตราจะไม่ถูกรวมและแอปจะแจ้งเตือน งบประมาณและยอดรวมแสดงได้เป็น THB หรือสกุลเงินท้องถิ่นของทริปเท่านั้น
- **Google Maps:** ไม่ใช้ API key จึงไม่ geocode และไม่คำนวณเวลาเดินทาง ลิงก์แบบย่อ (`maps.app.goo.gl`) เปิดได้แต่อ่านพิกัดไม่ได้ การเปิดแผนที่ต้องใช้อินเทอร์เน็ต
- **การวางรูปจากคลิปบอร์ด** ขึ้นกับเบราว์เซอร์ บน iOS อาจต้องแตะ "วาง" ในเมนูที่ระบบแสดง และปุ่มจะไม่แสดงถ้าเบราว์เซอร์ไม่รองรับ ใช้ "คลังรูป" แทนได้เสมอ
- **HEIC:** ถ้าเบราว์เซอร์ถอดรหัส HEIC ไม่ได้จะแจ้ง error (โดยปกติ iOS แปลงเป็น JPEG ให้เมื่อเลือกจากคลังรูป)
- **PDF ในแอป:** แสดงผ่าน iframe ซึ่ง iOS แต่ละเวอร์ชันแสดงหลายหน้าได้ไม่เหมือนกัน ใช้ปุ่ม "แชร์ / เปิดในแอปอื่น" เพื่อเปิดด้วยแอปไฟล์
- **ขนาด backup:** ทำในหน่วยความจำ บน iPhone ไม่ควรเกินประมาณ 250 MB
- **การจัดลำดับกิจกรรม:** ใช้ปุ่มขึ้น/ลงเฉพาะรายการที่ยังไม่กำหนดเวลา กิจกรรมที่มีเวลาจะเรียงตามเวลาเสมอ ยังไม่มี drag-and-drop
- **Bundle หลัก** ประมาณ 244 KB (gzip) โหลดครั้งแรกตอนออนไลน์ หลังจากนั้นถูก precache ไว้
- **Safari storage eviction:** ถ้าไม่ได้ติดตั้งลงหน้าจอโฮม Safari อาจลบข้อมูลเมื่อไม่ได้ใช้นาน จึงควรติดตั้งและสำรองข้อมูลเป็นประจำ
